# Valkey 核心知识

> Valkey 延续 RESP 与 Redis OSS 数据结构，同时在 Linux Foundation 治理下快速演进。关键是验证命令、持久化、模块和客户端兼容边界。

## 学习目标

在深入 Valkey 开发与运维前，建议掌握以下能力：

- [x] **能从 Redis OSS 评估迁移**
- [x] **能设计低延迟数据结构**
- [x] **能管理快速版本线**

## 必须建立的核心心智模型

### 01 RESP 与兼容性

大多数 Redis OSS 客户端可连接 Valkey，但新命令、模块和管理工具不会永久完全同步。

**关键实践要点：**

- 跑命令兼容测试
- 核对 ACL/协议版本
- 检查云服务支持

### 02 线程与内存

Valkey 在保持命令语义的同时持续优化 I/O、内存和多线程路径。

**关键实践要点：**

- 监控 latency doctor
- 避免大 key
- 按数据结构计算内存

### 03 持久化与集群

RDB、AOF、复制和 hash slot 仍是核心恢复与扩展机制。

**关键实践要点：**

- 验证文件双向兼容
- 演练 reshard
- 明确故障丢失窗口

## 工程决策落地指南

| 工程阶段 | 核心决策与行动要点 |
| :--- | :--- |
| **建模前** | 明确读写访问模式、一致性容忍度、数据生命周期与故障预算，再决定表结构、主键类型、分片键与索引策略。 |
| **上线前** | 基于生产规模的数据分布进行并发压测，记录查询计划（Query Plan）、内存/I/O 水位与高可用主从故障切换耗时。 |
| **运行中** | 监控 P95/P99 延迟分位数、连接池水位、长事务/慢查询与存储碎片；所有监控告警均需具备明确的 SOP 处置步骤。 |
