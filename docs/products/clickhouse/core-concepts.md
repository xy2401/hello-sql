# ClickHouse 核心知识

> ClickHouse 的性能来自 MergeTree、稀疏主索引、后台合并和列式向量化；表结构与 ORDER BY 往往比增加节点更重要。

## 学习目标

在深入 ClickHouse 开发与运维前，建议掌握以下能力：

- [x] **能设计分区键和排序键**
- [x] **能解释 parts/merges**
- [x] **能区分复制、分片和分布式表**

## 必须建立的核心心智模型

### 01 MergeTree 与排序键

数据按 part 写入并按 ORDER BY 排序，稀疏索引通过 granule 跳过数据。

**关键实践要点：**

- 排序键服务主要过滤路径
- 分区不要过细
- 检查 primary key 命中率

### 02 合并与变更

后台 merge 重写 parts；mutation、TTL 和去重都可能放大 I/O。

**关键实践要点：**

- 监控 part 数量
- 避免高频小批写入
- 理解 FINAL 的代价

### 03 集群拓扑

副本解决可用性，分片解决容量，Distributed 表负责路由。

**关键实践要点：**

- 明确一致性预期
- 设计 sharding key
- Keeper 需要独立容量规划

## 工程决策落地指南

| 工程阶段 | 核心决策与行动要点 |
| :--- | :--- |
| **建模前** | 明确读写访问模式、一致性容忍度、数据生命周期与故障预算，再决定表结构、主键类型、分片键与索引策略。 |
| **上线前** | 基于生产规模的数据分布进行并发压测，记录查询计划（Query Plan）、内存/I/O 水位与高可用主从故障切换耗时。 |
| **运行中** | 监控 P95/P99 延迟分位数、连接池水位、长事务/慢查询与存储碎片；所有监控告警均需具备明确的 SOP 处置步骤。 |
