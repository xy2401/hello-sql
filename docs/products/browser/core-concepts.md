# Browser Database 核心知识

> Browser Database 是浏览器原生数据库产品层：IndexedDB 提供事务对象仓库与索引，OPFS 提供文件持久化，Storage API 决定配额与持久化资格。

## 学习目标

在深入 Browser Database 开发与运维前，建议掌握以下能力：

- [x] **能设计 IndexedDB 的事务与索引**
- [x] **能区分 IndexedDB 与 OPFS 的职责**
- [x] **能管理浏览器兼容、配额和数据迁移**

## 必须建立的核心心智模型

### 01 对象仓库与索引

IndexedDB 以对象仓库保存结构化克隆记录，以主键和 IDBIndex 提供访问路径。

**关键实践要点：**

- 按访问模式设计 keyPath
- 避免无索引全库游标
- 升级事务中维护 Schema

### 02 事务生命周期

读写必须位于显式事务中；事务可能在当前任务结束且没有挂起请求时自动提交。

**关键实践要点：**

- 缩短读写事务
- 统一处理 request/transaction 错误
- 避免在事务中等待无关异步任务

### 03 OPFS、配额与同步

OPFS 适合数据库文件，Storage Manager 提供配额与持久化请求；跨设备同步仍需要应用协议。

**关键实践要点：**

- 在 Worker 使用同步句柄
- 检测 quota 与持久化状态
- 为清理、迁移和冲突设计恢复路径

## 工程决策落地指南

| 工程阶段 | 核心决策与行动要点 |
| :--- | :--- |
| **建模前** | 明确读写访问模式、一致性容忍度、数据生命周期与故障预算，再决定表结构、主键类型、分片键与索引策略。 |
| **上线前** | 基于生产规模的数据分布进行并发压测，记录查询计划（Query Plan）、内存/I/O 水位与高可用主从故障切换耗时。 |
| **运行中** | 监控 P95/P99 延迟分位数、连接池水位、长事务/慢查询与存储碎片；所有监控告警均需具备明确的 SOP 处置步骤。 |
