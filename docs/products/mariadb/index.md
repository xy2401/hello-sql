# MariaDB 概览

> **定位**：源自 MySQL 的社区驱动关系数据库，提供多存储引擎、Galera 集群与独立演进的 SQL 能力。

## 基础属性与架构形态

| 属性维度 | 规格与特性说明 |
| :--- | :--- |
| **数据模型** | 关系型 · MySQL 分支 |
| **查询接口** | 与 MySQL 高度相似但已产生显著方言与系统行为差异，不能假定完全兼容。 |
| **开源许可证** | GPLv2 |
| **部署形态** | 自托管、容器与部分云托管 · 适合偏好社区治理的 MySQL 用户 · 没有正式浏览器 WASM 内核 |

## 模型与查询语言

### 数据表达模型

关系表为主，可按工作负载选择 InnoDB、Aria、ColumnStore 等引擎。

### 查询交互方式

与 MySQL 高度相似但已产生显著方言与系统行为差异，不能假定完全兼容。

## 事务、索引与扩展机制

### 事务与一致性保障

- 事务能力取决于存储引擎
- InnoDB 提供 MVCC 与 ACID
- Galera 采用同步认证复制

### 索引与查询优化

- B-tree、全文与空间索引
- 虚拟列与函数索引能力随版本演进
- ColumnStore 采用列式执行路径

### 复制、分片与高可用扩展

- 主从复制与 Galera 多主集群
- Spider 等引擎提供分布式能力
- 读写扩展需要明确冲突策略

## 适用边界与选型决策

### 适合场景

- ✅ MySQL 兼容应用迁移
- ✅ 需要 Galera 或特定存储引擎
- ✅ 开源数据库基础设施

### 局限与约束

- ⚠️ 与 MySQL 的兼容差距会随功能扩大
- ⚠️ 驱动和托管生态小于 MySQL
- ⚠️ 迁移前必须执行真实 SQL 回归

::: tip 架构选型建议
只有在治理、Galera 或特定 MariaDB 能力带来明确价值时选择，不能仅把它当作可无缝替换的 MySQL。
:::
