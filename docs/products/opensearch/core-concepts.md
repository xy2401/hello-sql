# OpenSearch 核心知识

> OpenSearch 从 Elasticsearch OSS 分支演进出独立的搜索、可观测和向量生态；核心仍是 mapping、shard、segment 与插件兼容。

## 学习目标

在深入 OpenSearch 开发与运维前，建议掌握以下能力：

- [x] **能设计搜索索引**
- [x] **能管理插件版本锁步**
- [x] **能选择滚动升级或迁移方式**

## 必须建立的核心心智模型

### 01 搜索与向量索引

倒排索引、doc values、k-NN 与混合检索服务不同查询路径。

**关键实践要点：**

- 设计 analyzer
- 量化向量内存
- 评估混合排序

### 02 插件化平台

Security、Alerting、ISM、Observability 等插件与核心版本需要严格匹配。

**关键实践要点：**

- 维护插件清单
- 版本号锁步
- 升级前验证自定义插件

### 03 Shard 与生命周期

主分片、副本、segment merge 和 ISM 决定容量、恢复和冷热迁移。

**关键实践要点：**

- 控制 shard 数量
- 快照外置
- 演练 rolling restart

## 工程决策落地指南

| 工程阶段 | 核心决策与行动要点 |
| :--- | :--- |
| **建模前** | 明确读写访问模式、一致性容忍度、数据生命周期与故障预算，再决定表结构、主键类型、分片键与索引策略。 |
| **上线前** | 基于生产规模的数据分布进行并发压测，记录查询计划（Query Plan）、内存/I/O 水位与高可用主从故障切换耗时。 |
| **运行中** | 监控 P95/P99 延迟分位数、连接池水位、长事务/慢查询与存储碎片；所有监控告警均需具备明确的 SOP 处置步骤。 |
