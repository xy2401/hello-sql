# CockroachDB 概览

> **定位**：面向故障恢复和跨区域部署的 PostgreSQL 协议分布式 SQL。

## 基础属性与架构形态

| 属性维度 | 规格与特性说明 |
| :--- | :--- |
| **数据模型** | 分布式 SQL · 强一致 |
| **查询接口** | PostgreSQL wire protocol 与相近 SQL 方言。 |
| **开源许可证** | BSL / Commercial |
| **部署形态** | 提供自托管或云托管形态 · 浏览器只提供知识页，不模拟服务端集群 · 评估时必须验证版本、许可和云平台差异 |

## 模型与查询语言

### 数据表达模型

分片的关系键值模型与 Raft 复制。

### 查询交互方式

PostgreSQL wire protocol 与相近 SQL 方言。

## 事务、索引与扩展机制

### 事务与一致性保障

- 事务和一致性能力按产品工作负载设计
- 必须结合官方隔离级别和失败语义验证
- 跨节点事务会引入协调成本

### 索引与查询优化

- 核心访问路径依赖排序键、分区或列式统计
- 应使用 EXPLAIN/查询剖析验证
- 索引与物化结构会放大写入和存储

### 复制、分片与高可用扩展

- 支持计算或存储横向扩展
- 拓扑、数据分布和热点决定实际扩展效率
- 跨区域需要在延迟、一致性和成本间取舍

## 适用边界与选型决策

### 适合场景

- ✅ 跨区域高可用业务
- ✅ 需要水平扩展的事务系统
- ✅ 自动分片和副本调度

### 局限与约束

- ⚠️ 高争用事务代价高
- ⚠️ 与 PostgreSQL 并非完全兼容
- ⚠️ 跨区域拓扑设计复杂

::: tip 架构选型建议
当跨区域高可用业务是首要目标，且团队能够接受“高争用事务代价高”这一边界时，CockroachDB值得进入概念验证。
:::
