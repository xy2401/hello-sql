# Apache CouchDB 概览

> **定位**：以 HTTP、JSON 文档、MVCC 和多主复制为核心。

## 基础属性与架构形态

| 属性维度 | 规格与特性说明 |
| :--- | :--- |
| **数据模型** | 文档数据库 · 同步 |
| **查询接口** | Mango Query、MapReduce View 与 HTTP API。 |
| **开源许可证** | Apache 2.0 |
| **部署形态** | 以服务端集群或云托管为主 · 没有正式 WASM 的产品不提供伪在线运行器 · 本地演示应使用真实服务或官方模拟器 |

## 模型与查询语言

### 数据表达模型

文档数据库 · 同步的数据模型围绕主要访问路径设计，不应机械套用关系表范式。

### 查询交互方式

Mango Query、MapReduce View 与 HTTP API。

## 事务、索引与扩展机制

### 事务与一致性保障

- 事务范围和隔离能力依产品而异
- 跨分区或跨文档原子性需要单独确认
- 一致性级别必须与业务失败模型共同设计

### 索引与查询优化

- 索引必须服务已知访问模式
- 二级索引、全文或向量能力依产品实现
- 热点键和高基数字段需要专项治理

### 复制、分片与高可用扩展

- 通常通过分区与副本横向扩展
- 分区键决定数据局部性和负载均衡
- 跨区域复制需要明确冲突与一致性策略

## 适用边界与选型决策

### 适合场景

- ✅ 离线同步和多主复制
- ✅ 边缘节点数据收集
- ✅ HTTP 原生文档存储

### 局限与约束

- ⚠️ 查询能力弱于关系数据库
- ⚠️ 冲突需要应用处理
- ⚠️ 压缩与 View 维护有成本

::: tip 架构选型建议
只有当离线同步和多主复制带来的模型收益明显高于“查询能力弱于关系数据库”的代价时，才应以 Apache CouchDB 替代通用关系数据库。
:::
