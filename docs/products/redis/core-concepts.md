# Redis 核心知识

> Redis 的低延迟来自内存数据结构和单命令原子性。持久化、淘汰、复制与 Cluster 需要按数据丢失预算设计。

## 学习目标

在深入 Redis 开发与运维前，建议掌握以下能力：

- [x] **能选择数据结构**
- [x] **能计算内存与过期风险**
- [x] **能设计复制和 Cluster 故障切换**

## 必须建立的核心心智模型

### 01 数据结构与原子性

String、Hash、Set、ZSet、Stream 等提供不同复杂度；Lua/Functions 可组合原子逻辑。

**关键实践要点：**

- 先估算 O(N)
- 避免大 key
- 脚本必须有时间边界

### 02 过期、淘汰与持久化

TTL、maxmemory policy、RDB 和 AOF 分别解决生命周期、容量与恢复。

**关键实践要点：**

- 区分 expire 与 eviction
- 监控 fork/AOF rewrite
- 演练数据恢复

### 03 复制与 Cluster

异步复制意味着故障切换可能丢失已确认写入；Cluster 用 hash slot 分片。

**关键实践要点：**

- 理解 WAIT 的边界
- 使用 hash tag 控制多键操作
- 处理 MOVED/ASK

## 工程决策落地指南

| 工程阶段 | 核心决策与行动要点 |
| :--- | :--- |
| **建模前** | 明确读写访问模式、一致性容忍度、数据生命周期与故障预算，再决定表结构、主键类型、分片键与索引策略。 |
| **上线前** | 基于生产规模的数据分布进行并发压测，记录查询计划（Query Plan）、内存/I/O 水位与高可用主从故障切换耗时。 |
| **运行中** | 监控 P95/P99 延迟分位数、连接池水位、长事务/慢查询与存储碎片；所有监控告警均需具备明确的 SOP 处置步骤。 |
