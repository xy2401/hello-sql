# Redis 版本演进

Redis 采用大版本演进。自 7.4 起官方采用双重商业限制许可证（RSALv2/SSPLv1），同时开源社区由 Linux 基金会主导建立了 Valkey 分支。

## 核心版本演进与关键里程碑

### Redis 7.4（2024 年 7 月）

**主要功能与架构演进：**

- 引入 Hash 字段级别独立的 TTL（Hash Field Expiry），支持为 Hash 内部单个 key 配置独立过期时间
- 二次内存占用优化与 Hash 编码重构

**工程影响与选型建议：**

> 注意评估商业协议变更对企业自建或云服务提供的影响。

### Redis 7.2（2023 年 8 月）

**主要功能与架构演进：**

- 完善 ACL 细粒度权限控制与 Sharded Pub/Sub 分片发布订阅
- Redis 协议 RESP3 体验增强与集群元数据同步优化

**工程影响与选型建议：**

> Redis 最后一个纯正开源（BSD 协议）的主版本基线。

### Redis 7.0（2022 年 4 月）

**主要功能与架构演进：**

- Multi-Part AOF：彻底重构 AOF 持久化，消除 AOF 重写期间的内存翻倍暴涨
- Redis Functions：支持服务端常驻可持久化的脚本函数，作为 Lua 脚本的现代替代品
- Sharded Pub/Sub：支持将发布订阅流量绑定到 Cluster 单个分片

**工程影响与选型建议：**

> 持久化与服务端脚本能力的重大技术飞跃。

### Redis 6.2（2021 年 2 月）

**主要功能与架构演进：**

- 新增一系列针对 Stream、Set、ZSet 的原子操作命令（如 XADD 限制长度、ZRANGE 等）
- 优化了只读从节点的内存占用与复制握手

**工程影响与选型建议：**

> 6.x 系列的终极成熟稳定版本。

### Redis 6.0（2020 年 5 月）

**主要功能与架构演进：**

- 多线程网络 I/O（Threaded I/O）：网络读写支持多线程并行，命令执行仍保持单线程
- ACL 用户权限系统：支持基于用户角色、命令白名单与 Key 模式的访问控制
- 引入 RESP3 协议支持更丰富的数据类型

**工程影响与选型建议：**

> 高并发网络吞吐与企业级安全能力的里程碑。

### Redis 5.0（2018 年 10 月）

**主要功能与架构演进：**

- 引入全新的 Stream 数据结构，提供类似 Kafka 的持久化、多消费组流式消息能力
- 重构集群管理器：用 C 语言内置集群命令彻底替代旧版 redis-trib.rb Ruby 脚本
- ZSet 新增 POPMAX/POPMIN 等原子弹出命令

**工程影响与选型建议：**

> 确立了 Redis 作为轻量级高可靠流式消息队列的地位。

## 升级与数据迁移验证
